# Tool support matrix

How the five common coding-agent tools expose the pieces this playbook relies on. Verified on 2026-10-19 against each tool's official documentation (Claude Code at code.claude.com, Codex at OpenAI's developer docs, Cursor at cursor.com/docs, GitHub Copilot at docs.github.com and the VS Code docs, Gemini CLI at geminicli.com). These facts change monthly; re-check before relying on a detail, and open an issue when one moves.

## What this means for the templates

- **`AGENTS.md` plus a one-line `CLAUDE.md`** (`@AGENTS.md`) reaches every tool above with one file. Claude Code reads the import; Codex, Cursor and Copilot read `AGENTS.md` directly; Gemini CLI needs `AGENTS.md` added to `context.fileName`.
- **The guard and the stop check** ship for Claude Code ([settings](../templates/hooks/claude-code/settings.json)) and Codex ([hooks](../templates/hooks/codex/hooks.json)), whose hook shapes match. Cursor and Copilot have equivalent events (`preToolUse`, `stop`, `agentStop`) and a permission field in stdout; porting the scripts is a matter of the JSON key names. Gemini CLI's `BeforeTool` and `AfterAgent` events take a `decision` field. The Python scripts read the same stdin fields (`tool_name`, `tool_input.command`, `session_id`); check the event payload of your tool before trusting a port.
- **The allow list** belongs in the repository for Claude Code (`.claude/settings.json`), Cursor (`.cursor/permissions.json` or `cli.json`) and the Copilot CLI; Codex needs the project marked trusted before its `config.toml` applies; Gemini CLI's workspace policy tier is disabled by design, so allow rules go to the user tier and deny rules to the admin tier.
- **The deny list under managed policy** is possible in all five: Claude Code managed settings or MDM, Codex `requirements.toml` or MDM, Cursor's enterprise hook and permission paths, Copilot's organisation policies and device policies, Gemini CLI's admin policy folder.
- **Memory** as this playbook describes it (a folder of lesson files and an index) is native to Claude Code; for the others, keep the folder in the repository and point at the index from the instruction file.
- **Headless runs** exist everywhere, so the [eval runner](../templates/evals/run-evals.py) works with any of them through its `--agent` option.

## Caveats

- Codex documentation moved hosts in October 2026; links under `developers.openai.com/codex/` redirect. Expect further moves.
- Copilot's hook event names differ by surface (cloud agent, CLI, VS Code); the cloud agent treats an `ask` decision as a deny.
- Codex's hooks reference documents `permissionDecision: "deny"`; what it does with `ask` is not documented. The guard's main tier is `ask`, so on Codex expect those cases to block until you confirm the behaviour on your version, or edit the guard to return `deny` there.
- Claude Code reads `AGENTS.md` only when no `CLAUDE.md` exists in that directory, unless the combined setting is on; the one-line import avoids the question.
- Two details were not confirmed: Gemini CLI's import depth limit, and whether Cursor reads `CLAUDE.md` or the legacy `.cursorrules`.
