## Primary posts and guides

| Source | What we take from it |
|---|---|
| OpenAI, [Harness engineering: leveraging Codex in an agent-first world](https://openai.com/index/harness-engineering/) (2026-02-11) | A product of about a million lines with no hand-written code, around 1,500 merged pull requests, and roughly 3.5 pull requests per engineer per day over five months; `AGENTS.md` as a directory of about 100 lines, not an encyclopedia; `docs/` as the knowledge base; custom linters that enforce architecture; "garbage collection" of docs and debt; what the agent cannot see does not exist. The page is a JavaScript application that does not serve text to plain fetches, so the numbers are as reported by [Marmelab's survey](https://marmelab.com/blog/2026/09/24/the-state-of-ai-harness-engineering-2026.html) and secondary coverage. |
| Anthropic, [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) (2025-11-26) | The initializer agent (`init.sh`, a progress file, a feature list of 200+ items with `passes: false`, a first commit) and the coding agent (one feature per session; start ritual: `pwd`, git log, progress file, pick the highest-priority failing feature, run `init.sh`, run a basic end-to-end check first); "It is unacceptable to remove or edit tests"; browser testing "as a human user would". |
| Anthropic, [Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps) (2026-03-24) | Planner, generator and evaluator agents; the evaluator uses Playwright, screenshots, four weighted rubric criteria, sprint contracts and few-shot calibration; the retro game maker cost $200 and six hours with the harness against $9 and twenty minutes solo (unplayable); a second version without sprints on a newer model: $124.70 and 3 h 50; failure modes: context anxiety, self-evaluation bias, shallow testing, undetected stubs; "Every component in a harness encodes an assumption about what the model can't do on its own"; "Find the simplest solution possible, and only increase complexity when needed"; remove one component at a time. |
| Anthropic, [Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) (2026-01-09) | Code, model and human graders; capability versus regression evals; pass@k versus pass^k; "20–50 simple tasks drawn from real failures is a great start"; two experts must agree on pass or fail; give judges an "Unknown" out; isolated judges per dimension; "Grade what the agent produced, not the path it took"; read transcripts; watch for saturation. |
| Anthropic, [Claude Code hooks reference](https://code.claude.com/docs/en/hooks) (read 2026-10-19) | Event names (SessionStart, SessionEnd, Setup, UserPromptSubmit, Stop, StopFailure, PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied, SubagentStart, SubagentStop, PreCompact, PostCompact and more); hook types command, http, mcp_tool, prompt, agent; settings paths; exit 2 blocks; `hookSpecificOutput.permissionDecision` allow, deny, ask, defer; `stop_hook_active`; the eight-continuation cap. |
| OpenAI, [Codex hooks](https://developers.openai.com/codex/hooks) (read 2026-10-19; the URL redirects to OpenAI's documentation host) | Events SessionStart, SessionEnd, PreToolUse, PostToolUse, PermissionRequest, PreCompact, PostCompact, UserPromptSubmit, SubagentStart, SubagentStop, Stop, Interrupt; `.codex/hooks.json` or `[hooks]` in `config.toml`; exit 2 blocks; `permissionDecision`, `decision`, `continue`. |
| Birgitta Böckeler, [Harness engineering for coding agent users](https://martinfowler.com/articles/harness-engineering.html) (2026-04-02) | Agent = Model + Harness; guides (feed-forward: instruction files, skills, bootstrap scripts, codemods, language servers, CLIs) and sensors (feedback: static analysis, linters, tests, review agents, mutation testing, log analysis); computational versus inferential controls; maintainability, architecture-fitness and behaviour harnesses; harnessability; harness templates per topology; Ashby's law; "direct [human input] to where our input is most important". |
| Mitchell Hashimoto, [My AI Adoption Journey](https://mitchellh.com/writing/my-ai-adoption-journey) (2026-02-05) | "anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again"; an `AGENTS.md` entry per observed mistake, or a script announced there; plan and execute in separate sessions. |
| LangChain, [Improving Deep Agents with harness engineering](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering) (2026-02-17) | Terminal-Bench 2.0 from 52.8 % to 66.5 % with the model fixed: a four-phase system prompt (plan, build, verify, fix), pre-completion checklist, local-context and loop-detection middleware, time-budget injection, a "reasoning sandwich"; a different model on an earlier harness scored 59.6 %, so tune per model. |
| HumanLayer, [Writing a good CLAUDE.md](https://www.humanlayer.dev/blog/writing-a-good-claude-md) (2025-11-25) | Under 300 lines, ideally under 60; WHAT, WHY, HOW; progressive disclosure through a docs folder; "prefer pointers to copies"; no style rules (use linters and hooks); never auto-generate; models follow roughly 150–200 instructions and the tool's own prompt already spends about 50. |
| Lilian Weng, [Harness Engineering for Self-Improvement](https://lilianweng.github.io/posts/2026-07-04-harness/) (2026-07-04) | Seven editable components: system prompt, tool description, tool implementation, middleware, skill, sub-agent configuration, long-term memory; "the layer between the raw model and the real-world context seems to be as important as the model's raw intelligence"; open challenges: weak evaluators, memory lifecycle, negative results, diversity collapse, reward hacking, short horizons, the human role. |
| Marmelab, [The State of AI Harness Engineering 2026](https://marmelab.com/blog/2026/09/24/the-state-of-ai-harness-engineering-2026.html) (2026-09-24) | 246 harness repositories and 145 frameworks surveyed; the same model across eight harnesses on 25 tasks scored 68–88 %; Vercel removed 80 % of its tools and went from 80 % to 100 % success with half the tokens and latency from 724 s to 141 s; Microsoft's Azure SRE agent found that problems needing more than four handoffs almost always failed and rolled 50+ specialists back to one generalist; 60 % of harnesses have neither tests nor evals, seven have both; of 481 public `CLAUDE.md` files only 4.4 % of security rules had real controls; prose rules fail about 85 % of the time; reviewer agents reduced success by about 8 %; permission prompts were approved 93 % of the time; instructions raise reasoning tokens 14–22 %; five of 391 repositories measure harness usage; Stripe's "Minions" at about 1,300 pull requests a week with about 70 % merged without rework. All figures are the survey's. |
| Google Research, [Harness²: Recursive Agent Harnessing for an Open World](https://arxiv.org/abs/2610.14224) and [the repository](https://github.com/google-research/harness2) (2026-10) | "A harness is the system around a model that enables it to act as an agent: prompts, tools, memory, skills, orchestration"; eight editable components (system prompt, guardrails, memory, skills; tool guidance, scripts; subagents; plugins); Propose, Probe, Compose at task level; a persistent improvement harness at the harnessing level; gains of 11.5 points on WorkBuddy-Bench, 4.5 on JobBench and 11.8 points on LAB with frozen models. |

## Papers

| Paper | What we take from it |
|---|---|
| Galster et al., [Harness Engineering for Agentic AI Coding Tools: An Exploratory Study](https://arxiv.org/abs/2602.14690) (2026) | 2,853 repositories; eight configuration mechanisms from static context to executable and external; context files dominate and are often the only mechanism; `AGENTS.md` emerged as the interoperable standard; skills are mostly static text. |
| Barbaste et al., [Harness Engineering: Anatomy, Architecture, and Evolution of Coding Agents: A Source-Code Study of Eleven Systems](https://arxiv.org/abs/2609.00006) (2026) | Eleven harnesses, seven canonical subsystems, 29 recurring patterns; none use agent frameworks or vector retrieval; skills adopted by 9 of 11, MCP by 8 of 11; "behavioral policy migrating from prompt prose to configuration". |
| Fan et al., [An Empirical Study of Harness Design for Coding Agents](https://arxiv.org/abs/2609.20804) (2026-09-17) | 176 settings on SWE-Bench Verified and Terminal-Bench 2.1; context management matters most under tight budgets, mostly by preventing overflow; rule-based elision before summarisation is the most efficient; planning is an accuracy scaffold for weaker models and a cost saver for stronger ones; bash-only interfaces are cheaper for bash-proficient models. |
| Lin et al., [Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses](https://arxiv.org/abs/2604.25850) (2026-04-28) | Ten iterations raised pass@1 from 69.7 % to 77.0 %, above a human-designed harness at 71.9 %; harness edits as falsifiable contracts; structural elements (tools, middleware, memory) transfer across models with gains of 5.1 to 10.1 points, prose prompting does not. |
| de Macedo, [What makes a harness a harness](https://arxiv.org/abs/2606.10106) (2026-06-08) | The word is "loose and polysemous"; a necessary-and-sufficient definition validated on six real systems. |

## Field notes

Where a chapter cites "field notes" or "the authors", the source is the maintainers' own experience running coding agents across one product's six repositories (an API, a web app with a desktop shell, an admin panel, a marketing site and two mobile apps) over about three months in 2026, written down as lessons at the time. There is no public link; the numbers from it (the instruction file that grew to about 23,000 words, the token sample, the one-day rollout) are the authors' own measurements, not benchmarks, and are marked as such where they appear.
